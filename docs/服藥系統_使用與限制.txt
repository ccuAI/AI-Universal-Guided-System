一、這次完成的流程
首頁 → 吃藥小助手 → 新增用藥 → 拍攝／選取藥袋 → 中文離線文字辨識
→ 核對用藥資料 → 選擇提醒時間與療程 → 勾選確認 → 保存 → 本機通知
→ 今日服藥：已服用／跳過 → 歷史紀錄：查日期、撤銷誤記

也可以從「手動新增用藥」開始；辨識失敗時可對照原照片手動填寫。
一張照片含多個明確的「藥品名稱／藥名／品名：」時，依序確認各項候選。
取消後面的項目不會刪除前面已按「確認並保存」的項目。

二、怎麼操作
1. 從首頁進入「吃藥小助手」，按「新增用藥」。
2. 手機可拍攝或從相簿選藥袋；Chrome／桌面使用手動新增。
3. 核對每次用量與單位、用法；診所／醫院和備註可選填，不需填藥品名稱。
   每次用量以數字輸入，例如半錠填 0.5、單位填「錠」。
   用法未註明時可明確選「未註明」，不要自行解讀未知縮寫。
4. 固定服用選每日次數（1～12），每次都親自選時間，不能重複。
   「每日幾次」不等於「每隔幾小時」；目前只支援每日固定時刻。
   需要時服用則開啟開關；它不產生固定時間提醒，由你主動記錄。
5. 選開始日與 1～365 天療程，或明確選擇長期用藥。
   天數包含開始日；開始日可選至一年內，不自動採用 OCR 推定的日期。
6. 勾選已核對，按「確認並保存」。
7. 手機依提示允許通知。Android 可另外按「精準時間權限」設定。
   沒允許精準鬧鐘仍會採用非精準排程，畫面會提示可能延遲。
8. 看上方的排程狀態，確認已成功排程與最後提醒日期。
   保存用藥資料成功與排程成功是兩個獨立結果。
9. 服用後在「今日服藥」按「已服用」，或記錄「跳過」。
   需要時用藥按卡片的記錄圖示。誤記可在今日／歷史撤銷。
   未來日期只能預覽，不能預先記錄已服用。
10.「用藥計畫」可修改、停用或刪除；上方可篩選診所。
   「歷史紀錄」依日期顯示所有記錄，不受現有診所篩選影響。
11. 按左上返回鍵或從左邊緣向右滑回上一頁。
   中間的左右滑動用於切換分頁；保存進行中禁止離開確認表單。

三、手機／Chrome 差異
Android／iOS：
- ML Kit 中文文字辨識。Android 的 com.google.mlkit 原生依賴與 iOS 中文 Pod
  會在建置時放入 App；使用者首次辨識不需要另外下載中文模型。
- 本模組沒有藥袋照片的 HTTP 上傳或雲端 OCR。
- SQLite 保存計畫、每次事件與紀錄；藥袋照片複製到 App 私有文件目錄。
- 本機通知由手機系統在排定時間發送，不依賴 Flutter 畫面持續開啟。

Chrome／桌面：
- 支援手動建立、修改、停用、刪除與記錄，可預覽完整管理畫面。
- 用 SharedPreferences 的 JSON 快照保存預覽資料；瀏覽器資料屬於該來源。
- 不執行手機 ML Kit、相機藥袋辨識或手機本機提醒，也不保存藥袋照片。
- 換開發伺服器的 port／origin、清除網站資料或使用無痕模式會影響資料保留。
- 桌面／Chrome 資料不會自動移轉到手機。

四、文字辨識與核對
OCR 只擷取文字，MedicineParser 只整理有明確文字線索的候選值。
藥名需要明確標籤；用量只讀「每次 數字 單位」；頻率讀「每日 數字 次」；
療程讀明確天數；多個用法同時出現則留空。
沒有辨識到的欄位保持空白，不能直接產生通知。
不查藥物資料庫、不計算用藥劑量，也不推論處方、漏服後怎麼補服。
模糊、版面交錯、缺少標籤或 QD／BID 等縮寫都可能需要手動填寫。

五、通知的範圍與限制
1. 事件目前建立到今天往後 365 天，或較早的療程結束日。
2. 待排程通知本模組最多 iOS 60 則、Android 400 則。
   iOS 留一些空間給其他功能；Android 也保留系統及廠商限制的餘裕。
   這是本模組自己的上限，未保證其他模組未來占用更多通知時仍能排滿。
3. 依時間取最接近的事件排程。多項藥／一天多次會更快用完通知容量。
   畫面顯示最後排程日期；長期或尚有後續提醒時，會要求在該日以前開啟 App。
4. 啟動、回到 App、進服藥頁、保存／變更計畫與記錄狀態時更新排程。
   完全不再開啟 App，不能保證目前視窗以外的提醒仍會延伸。
5. Android 宣告重開機／更新接收器，恢復已交給系統的排程。
   強制停止 App、停用通知、裝置關機或廠商省電限制仍可能影響通知。
   被 Android 強制停止後應重新開啟 App 並檢查排程狀態。
6. 提醒使用裝置當地日曆時刻，回到 App 時會依裝置時區重建。
   旅行後仍是當地相同鐘點；不自動換成以原時區計算的服藥間隔。
   更改時區後請開啟 App，讓已排程通知更新。
7.「尚未紀錄」只表示沒有狀態紀錄，不直接判定已漏服。
   已過去的提醒時間不補發新通知，但當天清單仍可手動記錄。
8. 通知被拒絕後，系統可能不再顯示授權詢問；請從手機設定允許通知，
   再開 App 按「重新排程」。精準鬧鐘也須由 Android 設定頁允許。
9. 每次事件有固定通知 id；同步只變更新增／刪除／時區／精準模式不同的通知。
   已服用或跳過會移除對應通知。點通知開啟對應日期的歷史紀錄。

六、資料保存規則
- 手機的計畫變更與事件建立使用 SQLite 交易。
  預覽平台依序保存 JSON；保存失敗時恢復記憶體快照並顯示錯誤。
- 已服用／跳過的事件含藥名、用量與用法快照，不受後續計畫修改影響。
- 修改、停用或刪除計畫時重建／移除今天起尚未紀錄的事件。
  已記錄事件與以前的歷史保留；刪除計畫時清除它的照片。
- 新建立的計畫只從今天起產生事件，不回填之前日期的待服用事件。
- 照片保存在私有文件目錄，不依賴相機暫存；本版沒有額外加密或備份匯出。
- 資料目前以裝置為單位，沒有依登入帳號切換，沒有跨裝置同步。
  移除 App／清除 App 資料會失去本機資料。
- 原本 backfront/app.py 的上傳示範保留，但本服藥流程不呼叫它，
  不需要為此啟動 Flask 伺服器。
